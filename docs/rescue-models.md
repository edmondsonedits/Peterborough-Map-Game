# Reference-inspired rescue actors

The city explorer loads Blender-authored assets for the playable firefighter and pumper. Both retain procedural fallbacks when loading or validation fails. City readiness awaits both attempts. The November 2026 character update uses realistic on-foot speeds (1.6 m/s walk, 3.8 m/s run), while retaining the existing controls and acceleration response.

The firefighter retains the CC0 MakeHuman anatomical head, textured skin, eyes, brows and hair. The original turnout uniform has corrected charcoal fabric albedo so its folds, seams and pockets remain visible, refined reflective/leather materials and overlapping glove cuffs. A 19-bone weighted skeleton bends the elbows, knees, wrists and ankles, with pelvis/spine counter-motion and an articulated head. Three original authored clips supply breathing idle, heel-to-toe walking, and a distinct bent-arm running cycle with leg recovery and flight. They are phase-aligned and blended in Three.js using actual post-collision displacement, so pushing into an obstacle settles to idle.

This is an improved game character, not a photorealistic scan or motion capture. There is no facial/finger animation, dedicated turn/stop clip, or per-foot uneven-terrain IK. The existing surface system still places the character root on the ground.

The two-axle pumper uses a red/dark cab, chrome grille, pump gauges, silver roll-up lockers, hoses and roof ladder. Four independently rotating wheels include two steering pivots. Four warning lenses use the existing light switch. The rear and opposite side are approximate interpretations. Vehicle markings and UI labels are generic Fire Rescue.

Models are in `city-explorer/assets/characters/` and `city-explorer/assets/vehicles/`, with metadata beside each GLB. The character uses CC0 MakeHuman graphical data, not MakeHuman application code. Source/license records and hashes are in `city-explorer/assets/characters/licenses/`. The pumper and uniform geometry/markings are project-created. No user reference pixels, department insignia or manufacturer logos are embedded. All runtime textures are embedded in the character GLB; it makes no requests to third-party asset hosts.

For the current rigged character, run Blender 5.2 LTS with `--background --python tools/blender/build_firefighter_v3.py`. Its input is the retained self-contained `assets-source/characters/firefighter-v2.glb` (SHA-256 is recorded in runtime metadata), available from `city-explorer/assets/characters/firefighter.glb` in commit `8a21d9ce30691e5cf0838ee1b4acdaad9ecdfb37`. The editable result is `assets-source/characters/firefighter-v3.blend`; the shipping GLB has 106,674 triangles, 32 mesh primitives and is under 9 MB. Eye/hair textures are capped at 512 pixels; facial skin retains 1024 pixels. The original v1/v2 builders and source/license manifests are retained. Native sources live locally under the authorized H:/ChatGPT checkout and are not published.

The interactive model review is `docs/character-preview/index.html`, with head close-up, front/side/rear views, Idle/Walk/Run and pause controls. Local before/after render and gameplay evidence is under `artifacts/character-quality/`. The rigged character update is included in release v1.6.183.

Asset tests check size/budgets, self-contained textures, bone/clip validation, actual knee/elbow vertex deformation, loop continuity, sampled poses and rejected-export fallback preservation. Controller tests check speed blending, phase synchronization, frame-rate stability, nonfinite inputs and stopping. Startup tests protect the import-map wrapper and cache tokens. Browser checks verify decoded textures, rendered movement and the simulator loop. Physical mobile-device performance remains unmeasured.

Workflow references: [Blender animation and rigging](https://www.blender.org/features/animation/) for skinning and IK; [Blender MCP](https://github.com/ahujasid/mcp-for-blender) for the established LLM-assisted Blender workflow (this repository already uses local background Blender scripting); [Three.js AnimationAction](https://threejs.org/docs/pages/AnimationAction.html) for weighted clip playback; [Unity blend trees](https://docs.unity.com/en-us/engine/6000.0/manual/animation-section/animation-mecanim/animation-animator-controller/animation-state-machines/animation-blend-trees) for aligning foot-contact phases across different-duration cycles. [Mixamo's documented preparation rules](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html) informed the clean centered humanoid rig; no Mixamo asset or animation was downloaded or used.
