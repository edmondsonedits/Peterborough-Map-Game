# Mobile input lifecycle rebuild

This is a new implementation on base `f8818548ad903b14b22ee5a48a88f3abcd92f582`, not recovered bytes from the lost local batch. The existing single movement joystick, flight-command buttons, layout and analog encoding/handling are unchanged.

Each control has its own pointer owner. A second pointer cannot steal an active joystick or release an unrelated command. Key ownership is tracked separately for movement, action taps and each flight button, so expiry/release from one source cannot clear the same key held by another. Ordinary pointer-up releases only its control. Pointer cancel/lost capture on an active control, blur, pagehide, hidden visibility, gameplay mode/readiness changes and opening the menu interrupt all mobile input. Repeated interruption is idempotent for emitted key events; stale pointer moves do not resume canceled input. Cleanup clears the analog bridge before digital key releases, so its key-event suppression cannot leave a held digital key behind.

Run `node --test tools/test_mobile_input_lifecycle.cjs`. The test executes both complete production controller files in a minimal DOM event harness, including capture-before-bubble ordering. It covers simultaneous pointers, interleaved releases, repeated starts/stops, mode changes, all interruption paths, and overlapping action/flight key ownership. Initial regression run reproduced ownership/cleanup failures; the rebuilt implementation passes. This focused harness does not certify physical touch devices, browser pointer capture fidelity, gameplay motion or visual layout. The integrator must also run existing browser/mobile and driving QA against the final integrated build.
