# Compact feedback forms

The player should submit a problem or suggestion without reading internal diagnostics. Keep the location, reason, message and Send action prominent. Put the original location/circle/result, dataset/version, browser, viewport and report time behind a native, closed-by-default Technical details disclosure. Group every diagnostic in one content container and explicitly hide that container while closed so author layout rules cannot expose individual fields. Native disclosure preserves keyboard and screen-reader operation.

General bug/idea/question messages keep their automatically filled city/mode/department under Game details. These values remain editable and included in submission. Invalid required fields reveal their containing disclosure so validation can focus them. Preserve report snapshots, diagnostic text, message storage, developer review and AI exports exactly; no Firebase data or rule migration.

A disclosure is preferred to removing the information entirely because players can inspect what accompanies a report without navigating through it. Validate at the supplied screenshot's 338×656 CSS viewport, standard phone and desktop sizes, including keyboard open/close, Send visibility and identical attached data. Publish the next patch release.
